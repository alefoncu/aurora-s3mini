# Aurora S3 Mini

A minimalist, colourful, 2026-style redesign of a **Samsung Galaxy S3 Mini (GT-I8190N)** running **LineageOS 14.1 (Android 7.1.2)**: launcher, lock screen, status bar, notification shade, boot animation, icons, camera, system fonts and an automatic day/night mode — all built without patching the boot image and without touching the original system APKs.

> Personal project for one very old device (Cortex-A9 @ 1 GHz, 800 MB RAM). Everything is device- and ROM-specific and **modifies `/system`**. Read [Safety](#safety-and-reverting) before copying anything.
> Inspired by flat mobile design; contains no third-party artwork — every icon, wallpaper and animation is generated by code in this repo. Not affiliated with Samsung, Apple, Google or the LineageOS project.

| Piece | Description |

| **Day / night** | Automatic by time; also forceable; wallpaper, launcher, Settings, Calculator and notifications follow it |

## How it works (the interesting parts)

- **Static overlays (RRO) in `/system/vendor/overlay`.** Android 7.1 has no overlay manager, but anything in that folder is a static overlay. Each stock app gets a tiny overlay APK (colours, dimensions, vector icons, themes). `values-night/` variants are compiled by aapt2 and picked up when the system night mode changes.
- **Framework overlay.** Overlays targeting `android` are loaded by the native AssetManager (`/data/resource-cache/overlays.list`), so accent colours apply system-wide.
- **SystemUI overlay.** Status bar and quick-settings icons are regenerated as thin vectors by [`tools/gen_icons.py`](tools/gen_icons.py); the QS panel and tiles are glass drawables.
- **Day/night.** [`tools/device/daynight.sh`](tools/device/daynight.sh) runs from `/data/local/userinit.sh` (LineageOS `init.d`), computes day/night from the month and hour and calls `service call uimode 4 i32 1|2`; it also swaps the wallpaper through a tiny helper activity in the launcher. Override with `settings put system ios_theme_mode auto|day|night`.
- **Launcher** (`launcher2/`): plain Java, no support library. Icons are drawn in code from a line-glyph set ([`Glyphs.java`](launcher2/src/com/scratch/ios7launcher/Glyphs.java)) on gradient squircles.
- **Camera** (`camera/`): `android.hardware.Camera` + a software H.264/AAC recorder (`MediaCodec` + `MediaMuxer`), because the device's hardware H.264 encoder cannot start (`OMX.ST.VFM.H264Enc` error -1010).
- **Root without touching the ramdisk.** The base setup uses LineageOS's `addonsu` (installs `/system/xbin/su` only). Magisk-patching `boot.img` hangs this kernel; do not try it.

## Lessons learned (each cost a crash or a reboot)

1. **Notification card backgrounds must be opaque.** A translucent `notification_material_background_color` throws `background can not be translucent` in SystemUI, and every app that posts a notification is killed with `Couldn't expand RemoteViews`.
2. **Never override `status_bar_icon_drawing_alpha`** with `<item type="dimen" format="float">`: `PhoneStatusBarView` fails to inflate and SystemUI crash-loops.
3. **File-based resources (`res/anim/*`) in a framework overlay break `system_server`** (`FileNotFoundException res/anim-v1/...`) and leave the launcher black. Window animations cannot be overlaid on 7.1.
4. **An overlay style cannot reference the overlay's own resources** (`@color/…` → `Resource ID not found` in the app). Use literals or target resources.
5. **Animated vectors (torch, rotation, airplane, location) can be thinned, but keep every group/path name and animator target.** Look at what the animators actually touch: airplane/location/torch never animate the glyph path (swap fill→stroke freely); rotation morphs `device_1`/`body` between two paths, so replace *both* shapes everywhere (animators + static vectors) with the same node layout. A SystemUI overlay *can* override `res/anim` files (the lesson-3 failure was framework-only).
6. **Hard-coded text colours in layouts cannot be changed by an overlay.** Night variants of such apps give black-on-dark text; only own apps can do real dark mode.
7. **`WallpaperManager.setStream` can fail with "Invalid wallpaper data" on this ROM; `setBitmap` works.**
8. **Hardware H.264 encoder is broken** (`OMX.ST.VFM.H264Enc`), and removing it from `media_codecs.xml` makes `MediaRecorder` hang; encode in software with `MediaCodec`.
9. **If the home app crashes Android asks which launcher to use**: `cmd package set-home-activity com.scratch.ios7launcher/.HomeActivity`.
10. **`adb screencap` shows black for the camera viewfinder**; judge the preview on the device itself.
11. **`adb install` can hang or fail with `INSTALL_FAILED_VERIFICATION_FAILURE`** when Google Play services are stopped (the package verifier waits for them). The build scripts now push the APK and run `pm install -r` on the phone, which worked.
12. **Notification cards do not recolour when the system night mode changes** (they keep what they were inflated with); `daynight.sh` restarts SystemUI (`pkill -f com.android.systemui`) after a real switch. When starting the scheduler by hand use `setsid sh /data/local/ios/daynight.sh &`; `pkill -f daynight.sh` from inside `su -c '…daynight.sh…'` kills your own shell.
13. **A layout overridden in an overlay must keep the target's view ids.** `@+id/...` in the overlay creates new ids, and the app's `findViewById` returns null (`NullPointerException` in `ConditionAdapterUtils.bindViews`; Settings crashed on open). Fix: pass `--stable-ids ids.txt` to aapt2 with the target's ids (`work/settings/ids.txt`; `build_overlay.sh` picks it up automatically).
14. **Seeding test SMS**: `content insert` into `content://sms` is silently refused (only the default SMS app may write); insert with root `sqlite3` into `/data/user_de/0/com.android.providers.telephony/databases/mmssms.db` (set `thread_id` yourself) and compute timestamps in SQL (`strftime('%s','now')*1000`): shell arithmetic overflows 32 bits.
15. **File-based colours (`res/color/*.xml` state lists) ignore overlays** because the zygote preloads them before overlays apply. Redefine them as *plain* `<color>` values in the overlay (the cache key then becomes the colour value). Used for the Light text colours in `work/frame/res/values-night/colors_text.xml`.
16. **A day/night switch restarts SystemUI, which brings the lock screen back** (notification cards need it). It happens at the two daily switches; if that is annoying, switch the restart off in `daynight.sh`.
17. **Testing alarms**: `am broadcast -a com.scratch.iosclock.TEST -n com.scratch.iosclock/.AlarmReceiver --ei seconds 20` starts a timer that rings; to test a real alarm write `shared_prefs/clock.xml` (one line per alarm: `id\thour\tminute\tdaysMask\ton\tlabel`) as root and send `TIME_SET` to `.BootReceiver`; `dumpsys alarm | grep iosclock` shows it registered. A ring you did not expect may just be someone tapping Stop: the touch has `dev=10 src=0x1002`.
18. **Search must not rely on hand-written word lists.** Spelling/typo cases are handled by the matcher (phonetics, edit distance), meaning by Android metadata (`CATEGORY_APP_*`, `ACTION_DIAL`, `IMAGE_CAPTURE`, `ACTION_SET_ALARM`, labels in other locales). The only vocabulary left is one short list of words per *capability* in `AppIndex.java`, in Spanish and English; extend it there, never per app. `Fuzzy.java` is duplicated in `launcher2/`, `contacts/` and `phone/` (copy it after editing).
19. Boot animation frames can be small and centred with a solid background colour (`p 1 0 part0 #14123A` in `desc.txt`) — much lighter than full-screen frames.
20. **The hardware H.264 decoder is broken too, not only the encoder.** `OMX.ST.VFM.H264Dec` renders nothing to a surface (`numFramesTotal(0)` in `dumpsys media.player`) and `release()` deadlocks in mediaserver; on the UI thread that is an ANR (`kill -3 <pid>` + `/data/anr/traces.txt` showed `MediaPlayer._release` in binder). The stock player only survives because it is torn down with its window. Disabled in `media_codecs.xml` ([diff](tools/device/media_codecs_swavc.diff)); after changing it `killall mediaserver` reloads the list. Never call MediaPlayer/VideoView release on the UI thread here.
21. **Test screenshots saved under `/sdcard` show up in the Gallery** (and contain the wifi name). Save to `/data/local/tmp` with `su -c screencap` and pull.
22. **Seeding alarms: `am force-stop com.scratch.iosclock` first.** A running Clock keeps `SharedPreferences` cached, so a rewritten `clock.xml` is ignored and `TIME_SET` re-arms the *old* alarms. Also note that force-stop removes the app's alarms.
23. **Do not run `screencap` in a loop while the phone is booting.** The first cold-boot check with such a loop ended in a `system_server` SIGSEGV (`DeadSystemException`, framework restarted by itself) and a hung `screencap`; the second cold boot without it was clean (0 FATAL, 215 s uptime). Cause not proven; one occurrence in two boots.
24. **A matcher rule that only boosts an existing match is not a rule.** Initials were added as a score boost after a loop that already returned 0 when no word matched; test each mechanism on a query that *only* that mechanism can satisfy.

25. **Render home before building the semantic search index.** Package capability and translated-label queries can delay the grid on this hardware. Publish icons and name matching first, then enrich the documents in the worker. Refresh an already open query on the UI thread after indexing; `volatile` makes new documents visible but does not recompute displayed results.
26. **Review after theme transitions and after loading settles.** The scheduler can restore keyguard when it restarts SystemUI; Settings can initially show a blank surface. Check the actual foreground and wait for the list before treating a screenshot as visual evidence. Daytime clock text needs the ink token; white-on-pastel is hard to read.

## Build and install

Prerequisites (macOS shown): JDK 17, Android SDK platform 25 and build-tools 30.0.3, `adb`, a rooted device with `/system` remountable. The scripts assume the repository lives at `~/ios-reskin` and sign with the standard debug keystore (`~/.android/debug.keystore`).

```bash
adb pull /system/framework/framework-res.apk work/      # needed once, to compile overlays

# overlay APKs (one per target package)
tools/build_overlay.sh <Name> <target.package> work/<dir>
# then install into /system/vendor/overlay and reboot:
adb push out/<Name>Overlay.apk /data/local/tmp/
adb shell su -c 'mount -o remount,rw /system && cp /data/local/tmp/<Name>Overlay.apk /system/vendor/overlay/ && chmod 644 /system/vendor/overlay/<Name>Overlay.apk && mount -o remount,ro /system'
adb reboot

tools/build_launcher.sh      # builds and installs the launcher
tools/build_camera.sh        # builds and installs the camera
tools/build_phone.sh         # builds and installs the phone app
tools/build_gallery.sh       # builds and installs the gallery app
tools/build_messages.sh      # builds and installs the messages app
tools/build_contacts.sh      # builds and installs the contacts app
tools/build_clock.sh         # builds and installs the clock app
python3 tools/gen_icons.py   # regenerates the SystemUI thin icon vectors

# wallpapers and boot animation
java wallpaper/MakeWallpaper.java wallpaper/aurora.png
java boot2/MakeBoot.java boot2/pkg && (cd boot2/pkg && zip -0 -r ../bootanimation.zip desc.txt part0 part1)

# day/night scheduler
adb push tools/device/daynight.sh /data/local/ios/ && adb push tools/device/userinit.sh /data/local/
```

## Safety and reverting

- Overlays are plain files: delete the APK from `/system/vendor/overlay/` and reboot (from TWRP if the phone does not boot).
- Back up before changing system files (`fonts.xml`, `bootanimation.zip`, GravityBox prefs). Originals are **not** in this repo.
- Keep `adb` working: a SystemUI crash loop does not stop `adb`, so you can always remove the offending overlay.
- Always verify after each change: reboot, `sys.boot_completed=1`, no `FATAL EXCEPTION` in `adb logcat`.
